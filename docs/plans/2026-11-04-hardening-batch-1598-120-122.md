# Plan: hardening batch — fast-path labels (EW #1598), evil merge in mark-implemented (cp #120), owner-go test isolation (cp #122) (2026-11-04)

## In plain English
Three small safety fixes in one PR.
1. The conflict-resolution parser has a quick path that is only safe when the caller says which two commit ids the merge used. Today, forgetting that argument silently turns the safety check off. Make the quick path refuse instead.
2. `state mark-implemented` can count a line typed by hand into a later "clean" main merge as the accepted item's fix. Count a file only when one of the PR's own ordinary commits changed it, so nothing typed into a merge can pass as the fix.
3. Tests that fake the owner's chat answers write into the real owner-go folder with one shared fake identity, so concurrent test runs can see each other's records. Give each test its own fake repository name.

Current code is read at origin/main c7b5f8c, which already includes merged PR #140 (owner-granted extra round).

## Item 1 — #1598: fastSplit must not run without labels

### Problem
`pipeline/lib/resolution.mjs`: `parseConflictBlocks(M, S2, S3, tick, labels = null)` passes `labels` to `fastSplit`. Inside it, `labelled()` returns true for every line when `labels` is falsy (~line 101-105). Soundness of the fast path rests on a marker-shaped content trio being unable to carry the two commit ids of the merge that contains it. With no labels, a trio already sitting in a reviewed file (e.g. a test fixture) can be split off as a block. The head can then drop those fixture lines and get a `droppedTheirs` count instead of an `outside-edit` verdict. No new content can enter. The only production caller (`pipeline/lib/git.mjs:322`) passes `{ ours: fromSha, theirs: forkSha }` (full shas), so this is hardening, not a live bug.

### Design (chosen)
- `fastSplit` (~line 80): first statement after `tick`: `if (typeof labels?.ours !== 'string' || labels.ours === '' || typeof labels?.theirs !== 'string' || labels.theirs === '') return null;`. Delete the `if (!labels) return true;` line in `labelled()` (and the `labels?.` optional chaining on `ours`/`theirs`, now unnecessary). Returning null means "not applicable: use the exact parser", which is the existing contract.
- `parseConflictBlocks` keeps `labels = null` and is NOT made to throw. The exact parser (outside lines equal in M/S2/S3, sides rebuild both blobs byte for byte) does not depend on labels and is sound without them. Making the whole function demand labels would break its legitimate use on files without clean hunks and add a throw path for no safety gain.
- Update the two comments (the block above `fastSplit` says "Without `labels` any label is accepted" and the header notes) to say: without labels the fast path is skipped, so a file with clean hunks is `no-parse` (a counted round). Add one comment line at `git.mjs:322` that the labels are what makes the fast path legal.
- Rejected: throw / TypeError when labels are missing (breaks exact-parser callers and tests; the safe outcome is already "fall back").

## Item 2 — cp #120: a hand edit inside a later clean main merge counted as the fix

### Problem
`pipeline/commands/state.mjs` `markImplemented` (~line 214-255) measures "a non-test file changed since round N" as `git diff --name-only <base>..HEAD`. `<base>` comes from `effectiveReviewBase({from: round.toHead, forkPoint})`; on `whole-pr` (conflict) `baseAfterConflictMerge` (~189) picks the oldest default-branch merge with an exact base. In both paths the base is main merged into an old head, so a line typed by hand into a LATER main merge (an "evil merge": tree differs from the automatic merge of its parents) appears in the diff and is counted as the PR's own fix. Satisfies the "a non-test file changed" check without a real fix commit.
Wider than the issue text: the plain `synthetic` branch (round → one clean merge with an extra edited line, no conflict) has the same hole. `test/cli-review.test.mjs:638` already proves `codex-review` shows such a merge's edit; `mark-implemented` has no equivalent test.

### Design (chosen, revised after Codex plan review R1 and recheck R2): a file counts only when its FINAL content was written by a PR commit
`markImplemented`'s gate is "a non-test file changed since round N". Keep how `base` is computed today (`effectiveReviewBase`, and `baseAfterConflictMerge` on `whole-pr`) and the net diff `git diff --name-only --no-renames <base>..HEAD`. Then keep a path P only when its content at HEAD is EXACTLY a version that one of the PR's own non-merge commits since the round wrote:

1. `git log --no-merges --no-renames --raw --no-abbrev --format= <toHead>..HEAD ^<reviewBaseRef>` (one call). Each raw line `:<oldmode> <newmode> <oldblob> <newblob> <status>\t<path>` gives, per path, the blob each ordinary PR commit left (a deletion leaves the all-zero id). `^<reviewBaseRef>` drops commits from the default branch; commits brought in by merging another non-default branch are PR work and stay.
2. HEAD's blob per candidate path: `git ls-tree -r --full-tree HEAD -- <paths>` (absent ⇒ the all-zero id, i.e. deleted).
3. P counts iff P is in the net diff AND HEAD's blob of P ∈ { new blobs of P written by those commits }.

So:
- content typed into ANY merge commit (clean, conflict-resolving, octopus, a merge of another branch) never counts: the merge's result is not a blob any ordinary commit wrote (closes Codex R1-P1-2);
- change → revert → a merge edit of the same file (Codex R2-P1): HEAD's blob is the merge's, written by no ordinary commit → not counted; likewise when a merge discards or alters an earlier ordinary change;
- a genuine fix before a later merge that does not touch that file still counts (HEAD's blob is the fix commit's), closing R1-P2-3;
- a fix reverted to nothing is not in the net diff → not counted, as today.
Conservative case (accepted): if a later merge ALSO changed the fix's file (main edited it too, or a hand edit), that file no longer counts; any other fixed file still can. The refusal message says which file(s) and why; the remedy is a normal commit after the merge that finishes the fix in that file (any further real change re-establishes authorship). Today's counted set only shrinks, so this is fail-closed relative to today. Any git error or unparseable raw line → `base-unresolved`, as today.

Implementation (pipeline/commands/state.mjs, markImplemented): a named helper `ownAuthoredPaths({ root, config, toHead, paths })` returning the subset of `paths` whose HEAD blob an ordinary PR commit wrote, with a comment explaining why authorship (not touch) is the test and why merges never count. Call it inside the same `try` after `changed` is computed. Parse raw lines strictly (exactly the documented shape; anything else throws). `baseAfterConflictMerge` and its two-parent filter are unchanged (it only picks where the net diff starts).

Message: when non-test code paths in the net diff were dropped, the existing `no-code-change` refusal appends ` (their final content was not written by a commit of the PR — it comes from a merge commit: <up to 3 paths>; a change counts only when an ordinary commit of the PR wrote the file's current content)`.

Docs: `docs/cli.md` line ~121 and the `state mark-implemented` block (~403): one sentence: a file counts only when it changed since the round AND its current content was written by an ordinary (non-merge) commit of the PR, not by a merge or the default branch.

Rejected alternatives (one line each):
- Classify each later merge with `merge-tree` and restart measurement at the newest hand-written one (R0 of this plan): misses octopus merges unless more special cases are added, cannot recover when a genuine fix sits before the restart merge, and depends on merge-driver/attribute fidelity of the trial merge.
- Refuse (`base-unresolved`) when any later merge is hand-edited: unrecoverable and needs the same merge classification.

### Review-complete surfacing
No new refusal reason: exit-2 `no-code-change` leaves the item unmarked, `review-complete` says "accepted items are not implemented: <ids>", and the review loop (SKILL.md step 5) routes it back to the implementer, whose remedy (commit the fix as a normal commit) always works.

### Cost and git requirements
One extra `git log` over the PR's own commits since the round. No new git version requirement.

### Tests (test/cli-review.test.mjs, next to L1258; reuse `acceptedWorld`, `conflictMerge`, `fixA`, `mergeMainInto(..., { evil })`)

- a deletion fix (ordinary commit deletes a code file) → counted.
- unchanged behaviour (false-positive check, must stay green): L1258, L1246, L1216, L1146, the `base-unresolved` rebased-PR test (L1162), the other-branch conflict test (L1276).
